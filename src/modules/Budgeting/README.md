# Модуль «Бюджетирование»

Годовой бюджет фонда оплаты труда: отделы → строки (сотрудник или вакансия) →
12 месяцев с планом и фактом. Роут `/budgeting`, пункт меню в секции «Финансы».

**Статус: подключён бэкенд** — методы `budget_*` в `udevs-hrms-reports`
(`BUDGETING_DB_SCHEMA.md`). Mock-данных больше нет.

---

## Структура

```
src/modules/Budgeting/
├── index.tsx                     # страница: тулбар, полоса периодов, таблица, удаление
├── types.ts                      # BudgetDepartment / BudgetRow / BudgetMonth
├── constants.ts                  # ширины ячеек, форматирование, все суммы и разницы
└── components/
    ├── BudgetHead.tsx            # двухэтажная шапка: месяц + План/Факт/Разница/%
    ├── DepartmentRowLine.tsx     # строка отдела (итоги считаются, не правятся)
    ├── BudgetRowLine.tsx         # строка сотрудника или вакансии
    ├── AddRowLine.tsx            # «+ Строка»: сотрудник (постранично) или вакансия
    ├── AddDepartmentLine.tsx     # «+ Отдел»: выбор из справочника departments
    ├── AmountGroup.tsx           # группа колонок месяца — общая для строк и итогов
    ├── PositionPicker.tsx        # должность вакансии — выбор из справочника
    ├── StatusPicker.tsx          # статус строки — свой поповер вместо <select>
    ├── MoneyCell.tsx             # сумма, правится по клику
    └── EditableText.tsx          # название, должность, проценты — правятся по клику
```

## Решения, которые стоит знать

- **Отделы — существующий справочник `departments`.** Своего списка у бюджета
  нет: два набора названий в системе разъехались бы, и отчёт «бюджет против
  факта по отделам» пришлось бы сшивать руками. Поэтому отдел в таблице не
  переименовывается (правится в настройках), «+ Отдел» — выбор из справочника,
  а «убрать» уносит из бюджета строки отдела, а не сам отдел. Отдел считается
  «в бюджете», когда в нём есть строка; только что выбранный пустой отдел живёт
  в состоянии страницы, пока в него не добавят первую строку.
- **Два типа строк, один компонент.** Сотрудник и вакансия отличаются двумя
  полями: у сотрудника имя и должность приходят из его профиля и здесь не
  правятся (бюджет не место, где меняют кадровые данные), у вакансии имя —
  произвольная пометка, а должность выбирается из справочника `positions`.
  Свободного текста в должности нет намеренно: «Frontend» / «фронтенд» /
  «Frontend-разработчик» разъезжаются, и такой бюджет потом не сопоставить с
  вакансиями рекрутинга.
- **Итоги считаются снизу вверх и не правятся.** Отдел и «Итого» — производные
  от строк: иначе итог и сумма слагаемых разъезжаются, и непонятно, какой цифре
  верить.
- **Налог % и Бонус %** — справочные: на суммы в ячейках не влияют, суммы вводят
  готовыми. Поля нужны, чтобы не держать проценты в голове при планировании.
- **Три масштаба: месяцы, кварталы, годы.** Данные всегда лежат помесячно, вид
  только группирует их. Квартал суммирует свои три месяца, а годовой вид ставит
  колонкой **каждый год** — текущий ±2 плюс все годы, где бюджет уже заведён.
  Он существует ради сравнения, поэтому переключатель года в нём скрыт (сравнивать
  нечего, если год один), а суммы только для чтения: непонятно, в какой месяц
  записать введённое. Строки и отделы сопоставляются между годами по id.
- **Раскладка как у KPI.** Тулбар во всю ширину (сводка года строкой слева,
  поиск / колонки / свернуть / «+ Отдел» справа), под ним полоса с масштабом и
  годом, дальше таблица во всю высоту. Карточек-итогов нет намеренно: те же
  цифры уместились в строку, а сотня пикселей высоты досталась таблице. Выбор
  колонок живёт в выпадашке у своей кнопки: полоса под тулбаром принадлежит
  фильтрам, занимать её настройкой вида нельзя.
- **У липкой колонки непрозрачный фон и граница справа.** С полупрозрачным
  (`bg-…/60`) сквозь неё просвечивали уезжающие цифры, а без границы не видно,
  где колонка кончается. Это же правило действует и на подсветку строки при
  наведении.
- **По умолчанию виден только план.** Факт, Разница и Отклонение % включаются
  по отдельности в меню «Колонки»: план заполняют и перечитывают постоянно, а
  факт и отклонения смотрят по закрытым месяцам. Ширина таблицы — 1900px с одним
  планом против 5700px со всеми четырьмя колонками.
- **Год — отдельный набор данных.** Переключатель года показывает другой бюджет,
  а не тот же с другой подписью; новый год начинается с той же структуры отделов
  и людей (с теми же id — по ним годовой вид и сопоставляет строки), но без сумм.
- **Строка отдела выделена как группа в KPI**: заметный фон, цветная засечка
  слева, жирное название и счётчик строк. В таблице на полсотни колонок граница
  между отделами должна ловиться взглядом, без чтения названий.
- **Первая колонка и строка «Итого» прилипают** к краям прокрутки: без названия
  строки цифры справа не читаются, а к итогу возвращаются после каждой правки.
  У липкой колонки непрозрачный фон и граница справа — с полупрозрачным сквозь
  неё просвечивали уезжающие цифры.
- **Вертикальная прокрутка одна.** Страница фиксирована по высоте
  (`h-[calc(100vh-76px)]`), прокручивается только таблица — иначе рядом жили бы
  два скролла, свой у таблицы и общий у макета.
- **Ширины колонок считаются в одном месте** (`groupWidthPx`, `TITLE_CELL`,
  `STATUS_CELL`, …), и в ширину группы входит пиксель разделителя: у групп в
  строках `border-l` добавляется к сумме ячеек, а в шапке ширина задаётся
  числом — без этой единицы шапка уезжала от строк на пиксель за период.
  Отступы текста тоже общие: значение и подпись выровнены по правому краю до
  пикселя, включая прозрачную рамку у редактируемой ячейки.
- **Отдел добавляется строкой в конце таблицы**, а не кнопкой в тулбаре: как и
  строка внутри отдела, действие стоит там, где появится результат.

## Данные

`src/api/services/budget.service.ts` — шлюз `udevs-hrms-reports`:

```ts
useBudgetQuery(year, years)      // { departments, rows, amounts, employees, positions }
useClearBudgetDepartment(years)  // убрать отдел из бюджета (его строки и суммы)
useSaveBudgetRow(years)          // upsert строки; новому сотруднику сервер ставит оклад
useDeleteBudgetRow(years)        // строка + её суммы
useSaveBudgetAmount(years)       // одна ячейка: строка + год + месяц, план или факт
```

- **Ключ запроса зависит от годов**: помесячный и квартальный виды просят один
  год, годовой — окно вокруг текущего. Это разные наборы данных, а не срезы
  одного.
- **Правки оптимистичные**: бюджет заполняют ячейка за ячейкой, ждать ответ на
  каждую значит превратить работу в череду замираний. Ошибка откатывает
  состояние и показывает тост.
- **Плоский ответ → дерево**: сервер отдаёт отделы, строки и суммы отдельными
  списками, страница сшивает их в «отдел → строки» с суммами выбранного года —
  компоненты таблицы про формат API не знают.
- **Сотрудники грузятся не бюджетом.** `budget_get` их не отдаёт: список нужен
  только выпадашке «+ Строка», и она берёт его тем же запросом, что и страница
  «Сотрудники» (`useEmployeesQuery`) — постранично, с поиском на сервере и
  подгрузкой при прокрутке. Побочный эффект того же решения: в списке нет
  служебных записей `user_base` без имени, потому что запрос отбирает людей по
  роли сотрудника и активному статусу.
- **Оклад при добавлении сотрудника** ставит сервер, из `employee_works.salary`
  (см. `BUDGETING_DB_SCHEMA.md`): двенадцать одинаковых сумм руками — работа,
  которую он может сделать сам. План идёт на весь год, факт — только за
  закрытые месяцы, иначе отклонение было бы нулевым до декабря.

## Что дальше

- Факт со временем должен подтягиваться из расчёта зарплат, а не вводиться
  руками; ручной ввод останется для месяцев, где расчёта ещё нет.
- Порядок отделов и строк меняется только на сервере (`sort_order`), в UI
  перетаскивания пока нет.
- Ключ модуля `budgeting` заведён в каталоге ролей фронта
  (`Settings/Roles/moduleCatalog.ts`); на бэкенде (`hrms-roles-common.js`) его
  ещё нет — синхронизировать.
