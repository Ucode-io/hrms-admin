# Раскладка формы сотрудника (конструктор в самой форме)

Расположение полей формы сотрудника настраивается **внутри формы**, а не в настройках:
кнопка «Настроить форму» в шапке `/employees/new` и `/employees/:id/edit` переключает
её в режим конструктора. Справочник самих динамических полей живёт отдельно —
`/settings/custom-fields` (см. `src/modules/Settings/CustomFields/README.md`), там
только создание/изменение/удаление полей, без расположения.

## Как устроено

```
EmployeeFormLayout
  ├── cards[]  id, title, description, column ('left' | 'right'), system, locked, sortOrder
  └── items[]  id, kind ('static' | 'dynamic'), cardId, width ('half' | 'full'), sortOrder
```

- **`static`** — поле из `staticFields.tsx`: реестр «ключ → label + render(ctx)».
  Рендер и привязка к react-hook-form живут в реестре, поэтому **payload от
  расположения не зависит** — `onSubmit` как собирал объект по ключам, так и собирает.
- **`dynamic`** — поле из схемы Custom Fields (таблица `user_base`, `system: false`),
  `id` = guid поля в `hrms_custom_fields`. Рендерится через `DynamicFieldControl.tsx`
  в стилях формы. Поле привязано к react-hook-form под именем `custom_data.<ключ>`,
  поэтому правила справочника (обязательность, длина, диапазон, регулярное
  выражение, дата) **реально блокируют сохранение**. Значения уходят в payload
  вместе с формой, но только когда сервер сообщил `entity.values_field` —
  то есть когда у `user_base` заведено поле `custom_data` (тип JSON).
  Исключение — тип «файл»: контрола ещё нет, поле к форме не привязывается,
  поэтому `required` на нём ничего не блокирует.
- Хранилище — сервер: таблица `hrms_form_layouts`, методы `form_layout_get` /
  `form_layout_save` в `udevs-hrms-reports` (см. `FORM_LAYOUT_DB_SCHEMA.md`).
  Правки копятся локально и уходят **одним запросом по кнопке «Готово»** — иначе
  каждое перетаскивание было бы отдельным сохранением. Пока правки не сохранены
  (`isDirty`), ответ сервера не перетирает состояние.
- На сервер уходит «сырое» состояние, а не результат `reconcile`: если справочник
  динамических полей ещё не догрузился, `reconcile` временно прячет их элементы —
  сохранив такой результат, потеряли бы раскладку из-за подвисшего запроса.

## Карточка сотрудника читает ту же раскладку

`/employees/:id` (`src/modules/Employees/Detail/index.tsx`) показывает значения
динамических полей **там же, где админ разложил их в конструкторе**: карточка
`crd_personal` дописывает строки в секцию «Личное», `crd_contacts` — в
«Контакты» (соответствие в константе `DETAIL_CARD_SECTIONS`), а остальные
карточки раскладки, где есть динамические поля, рисуются отдельными секциями
перед «Интересами». Второй настройки для детальной нет и не планируется.

Форматирование значения по типу поля — `Settings/CustomFields/formatValue.ts`
(`select` → название варианта, `boolean` → Да/Нет, `date` → 31.07.2026,
`money` → разряды, `email`/`phone`/`url` → ссылка). Пустое поле показывается
как «—», чтобы было видно, что оно вообще есть.

## Тот же механизм у модалки «Добавить должность»

Модалка в карточке сотрудника (`Detail/components/work-layout/`) настраивается
так же: свой реестр полей `workFields.tsx`, своя раскладка с
`entity_slug = 'employee_works'` и одна карточка `crd_work_modal` (в окне 700px
управлять карточками незачем — только порядок и ширина). Хук общий:
`useFormLayout(entitySlug, dynamicFieldIds, registry)`; `useEmployeeFormLayout` —
обёртка над ним. Плитка конструктора (`SortableTile`) экспортируется из
`FormLayoutArea` и переиспользуется как есть.

## Правила, которые легко сломать

- **Обязательные статичные поля** (`required` в реестре: фамилия, имя, эл. почта)
  убрать из формы нельзя — в конструкторе у них замок вместо крестика, а
  `reconcile()` в хуке вернёт их в первую карточку, если они пропали из сохранёнки.
- **Карточка «Рабочие данные» вне конструктора** (`locked: true`): её состав не
  настраивается — это данные `employee_work`, которые пишутся отдельным запросом при
  создании. В режиме конструктора она не показывается вовсе, в режиме заполнения
  ведёт себя как раньше (правая колонка 400px, только при создании).
- **Правая колонка = только создание** (`showRightColumn = !builderMode && !isEdit`).
  Новые карточки создаются всегда в левой колонке.
- **`createOnly`-поля** (оклад, причина изменения) скрываются в режиме
  редактирования независимо от того, в какой карточке лежат: их пишет только
  `createEmployeeWork` при создании.
- **Системные карточки** (`system: true`) удалить нельзя, переименовать и
  перетащить — можно. Поля из них выносить разрешено.
- Удаление карточки убирает только раскладку её полей: сами поля попадают в список
  «Вне формы» и их можно вернуть кнопкой «+ Поле».

## Добавление поля

Поле кладут в карточку кнопкой **«+ Поле» в её шапке** — так из самого действия
видно, куда оно попадёт (глобальный выбор карточки списком оказался непонятным).
Сверху остаётся справочная плашка «Вне формы: N» с перечнем неразложенных полей,
кликов она не принимает.

Ширина меняется **перетаскиванием правого края плитки** (`SortableTile` +
`.efb-resize-edge` в `src/index.css`), как у нативного ресайзера: во время drag
плитка тянется за курсором, бейдж над ней показывает, к какой ширине она
прилипнет, фиксация — **при отпускании** (цель: `projected > (half + full) / 2`).
Двойной клик по краю переключает без drag.

⚠️ Два невидимых инварианта ресайза:
- **Живая ширина НЕ ставится на grid-элемент.** `1fr`-колонки — это
  `minmax(auto, 1fr)`: растянутый элемент раздувает min-content своей колонки,
  и плитки в соседних рядах меняют ширину. Поэтому во время drag ячейка
  замораживается (обёртка получает только `height`), а плитка рендерится
  абсолютным «призраком» поверх сетки; на месте ячейки — пунктирная «дырка».
- **DOM-узлы не должны пересоздаваться при старте ресайза** — pointer capture
  привязан к элементу края. Поэтому у «дырки» и живого слоя стабильные `key`,
  а `setPointerCapture`/`release` обёрнуты в try/catch (на синтетических
  pointerId они кидают и без этого молча обрывали обработчик).

Добавленное поле **подсвечивается и прокручивается в центр экрана**: класс
`.employee-form-field-added` (keyframes `employeeFormFieldDrop` в `src/index.css`),
контур цвета бренда через `--employee-form-accent`, гаснет за ~2 с.

## DnD

Плитка поля переносится **за любое место** (listeners dnd-kit висят на обёртке,
`activationConstraint: distance 6`), а не за отдельную ручку; иконка-грип осталась
как визуальная подсказка. Кнопка удаления и край ресайза гасят `pointerdown`
(`stopPropagation`), чтобы не запускать перенос. Во время ресайза сортировка
плитки отключена (`useSortable({ disabled })`).

Остальная связка та же, что и в других модулях: `pointerWithin` → `rectIntersection`,
`rectSortingStrategy` для полей, `verticalListSortingStrategy` для карточек,
отдельный droppable `items:<cardId>` (чтобы можно было бросить в пустую карточку),
`onDragOver` переносит поле между карточками на лету, `DragOverlay` + `CSS.Translate`
(`CSS.Transform` добавляет scale и ломает вёрстку).

При отладке в браузере: симуляция перетаскивания слишком «быстрыми» событиями
не срабатывает — нужен `pointerdown`, **10+** промежуточных `pointermove` через
`setTimeout` и пауза перед `pointerup`.
